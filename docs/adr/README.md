# ADR (Architecture Decision Record)

결정을 내릴 때마다 파일 하나. **나중에 몰아 쓰면 이유를 잊습니다.**

파일명: `NNNN-짧은-제목.md` (예: `0001-order-delivery-async.md`)

## 템플릿

```markdown
# NNNN. 제목

- 상태: 검토중 | 채택 | 폐기 | 대체됨(→ NNNN)
- 날짜: YYYY-MM-DD

## 맥락
왜 이 결정이 필요했나. 당시 제약(일정, 규모, 기존 구조).

## 선택지
- A: ...
- B: ...
- C: ...

## 결정
무엇을 골랐나.

## 결과
얻은 것과 **포기한 것**. 포기한 걸 안 쓰면 ADR이 아니다.

## 다시 본다면
지금 같은 상황이면 어떻게 할 것인가. (나중에 채워도 됨)
```

## 왜 쓰나

`이력서/경험 정리 템플릿.md` 의 "기술 선택과 트레이드오프" 칸과 같은 형식입니다.
ADR을 쌓으면 면접 답변이 자동으로 쌓입니다. 코드는 잊어버려도 ADR은 남습니다.
